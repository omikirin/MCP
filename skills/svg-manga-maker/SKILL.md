# SVG漫画メーカー

小説→ネームJSON→ページSVG/PNG を全自動で通すパイプライン。核心思想は **「自由描画をやめて選択問題にする」**:
ネームは5辞書のID参照のみで記述するため、LLMが書いても必ずレンダリング可能で破綻しない。

## 全体像

```
[素材制作]  発注プロンプト → GPTで線画シート生成 → 抽出/マスク → キャラ別ライブラリ
[執筆]      小説 → ネームJSON(辞書ID選択) → render.py → ページSVG → PNG配信
```

## 5つの辞書 (references/)

| ファイル | 内容 | ネームJSONでの参照 |
|---|---|---|
| layouts.json | コマ割り38種。1000×1414正規化座標、右綴じ、**コマ配列は右→左読み順** | `layout_id` |
| poses.json | 90基本ポーズ×5アングル=450。emotion/energy(1-5)/persons/shotタグ | `pose_id` (例 P029_side) |
| expressions.json | よしながふみ式3連ビート15種×3ステップ=45表情 | `beat_id` (例 BEAT03) |
| onomatopoeia.json | 描き文字100。placement/intensity/style | `sfx[].text` |
| backgrounds.json | 背景100(実景85+効果背景15)。BG086集中線〜は演出用 | `background_id` |
| characters.json | CryptoNinja 42キャラの枠・進捗・発注ルール(宇迦#015=完備495、於兎#006=ポーズ438+表情45) | アセットdir解決 |

## ネームJSONスキーマ

```json
{"layout_id":"3段ビート中",
 "panels":[
  {"pose_id":"P030_front","background_id":"BG001",
   "serif":["短い台詞", {"t":"形状指定つき","shape":"震え"}],
   "sfx":[{"text":"ドン","intensity":5}],
   "pose_x":0.5},
  {"beat_id":"BEAT03","serif":["…うん"],"sfx":[{"text":"ポッ"}]},
  {"chars":[{"pose_id":"P001_front","x":0.25},
            {"pose_id":"P006_front","char":"006_oto","x":0.75,"flip":true}],
   "serif":["複数キャラ同時"]}
 ]}
```

- `chars` 配列で1コマ複数キャラ: `x`(0-1横位置)/`scale`/`flip`(左右反転)/`char`(characters/<slug>切替)。**配列の後ろほど手前**に重なり、白マスクが前後関係を自動処理

- **panels配列の1番目=ページ右上のコマ**(レイアウト定義が右→左順)。ページ束も右綴じ(P1が右)
- `beat_id` は3コマに自動展開(カメラ同ポジ・背景なし・セリフとSFXは3コマ目のみ)
- serifのフキダシ形状: 標準/叫び/トゲ/震え/ひそひそ/角丸。「!」入りは自動で叫び。**雲は廃止**(指定されても標準に落ちる)
- serifは1コマ2個まで推奨。1個目=右上、2個目=左やや下に自動配置
- sfxは**キャラ非重複が絶対**: 10候補位置→縮小→それでも無理なら描画省略(レンダラが保証)

## レンダリング

```bash
cd <作業dir>  # 辞書JSON・ライブラリdirがある場所
python3 scripts/render.py name.json page.svg
python3 -c "import cairosvg;cairosvg.svg2png(url='page.svg',write_to='page.png',output_width=1080,background_color='white')"
```

前提ディレクトリ(render.pyのカレント):
- `vectors_svg/` = 使用キャラのポーズセル(characters/<slug>/poses/ をコピー/リンク)
- `vectors_expr/` = 表情ビートセル
- `backgrounds_lib/` = BG###.svg
- `sfx_lib/` = <語>.svg(無い語はフォント→パス化フォールバック)

レンダラの保証事項: 縦書きセリフは**Noto Serif CJK JPのグリフをパス化して埋め込み**(フォント非依存・環境で崩れない)。フキダシはコマ高さ7.5%基準で自動スケール+コマ内クランプ+収まらなければ縮小。効果背景はbackgrounds_libに実物が無ければ手続き描画(集中線等)にフォールバック。

配信はマスターSVG→PNG書き出し(1080px≒86KB/頁)が軽くて確実。

## 素材制作パイプライン

### 1. 発注
```bash
python3 scripts/sheet_planner.py poses|sfx|bg   # sheets/ に発注プロンプト生成
```
新キャラは characters.json の ref_image(公式CC0絵)+ 既存キャラのスタイルリファレンス画像を添付し、
プロンプト冒頭にキャラ指定ブロックを差す(oto_orderの前例参照)。
**発注鉄則**: 各カット間に十分な余白(接触・重なり・はみ出し禁止)/黒一色線画・白背景/同一頭身/番号は絵から離して/600DPI相当。

### 2. シート処理(ポーズ)
```bash
python3 scripts/process_sheet.py <sheet.png> <シート番号> <体数>
# 内部: 健診(黒潰れ/空白検出)→低解像度なら×4以上アップスケール→vtracerトレース
#       →cluster_slicer(成分クラスタ→ID割当→タイト切り出し)→masker→library統合→検品PNG
```
シートに罫線や番号(上/下どちらでも)がある場合は `pose_sheet_extract.py`(罫線=インク率プロファイル除去、番号=上下ゾーン検出)。
密集シートで割当が崩れたら `GRID_FIT=1`(kmeans軸)か、最終手段は **成分マスク+等間隔軸方式**(scripts/reextract.py)。
表情シート(9行×5列)は `expr_extract.py` — 番号は「セル最大成分(顔)の上端より完全に上の成分をサイズ不問で全撤去」ルール(顔パーツは顔クラスタに連結しているため誤爆しない)。
背景は `bg_extract.py <png> <開始番号>`、オノマトペは `sfx_extract.py <png> <開始index>`、どちらもラベル文字を自動除去。

### 2.5 高精細化(Brain級)
セルあたりの作業解像度を約1500pxに揃えると線が滑らかになる(hires_sheet.py / hires_mini.py: ×8〜10アップスケール+corner_threshold 55/length_threshold 3.5)。ソースPNGの実解像度以上の情報は増えない点に注意(補間では細部は生まれない)。
仕上げに svg_shrink.py で座標を整数丸めすると容量-40%(品質影響なし)。

### 3. マスク焼き込み
```bash
python3 scripts/masker.py <in_dir> <out_dir>
```
各セルをラスタ化(マスク用は720px上限で十分)→**EDT(距離変換)ベースの強力closing(短辺8%)**→シルエットトレース→**白fillパスを最下層に挿入**。
開いた輪郭の画風でも内部まで白が届く。検品は「市松背景でシルエット内部の透け率」を測る(5%超はNG)。
これでキャラ/SFXは「背景に勝つ自己完結素材」になり、重ね順の管理が不要になる。背景セルにはマスク不要。

### 4. 検品→ピンポイント修正
必ずID+名前ラベル付きのオーバービューPNGを生成してユーザーに目視確認してもらう。
ズレ報告(例「P029_side がおかしい」)には reextract.py で該当行/セルだけ切り直して差し替える。
機械検品: 複数キャラ疑い(第2連結成分>15%)・縦横比異常・黒密度(線画は5〜20%が健全)。

## ハマりどころ(実戦で踏んだ地雷)

1. **ベクター納品のstroke-width異常**: ツールが全パスに24.8等の過大線幅を付けることがある→切り出し時に正規化(STROKE_W env)
2. **vtracerの複合パス**: 複数図形が1つの`<path>`のサブパスに入る。クラスタ判定はサブパス分解で行うが、**出力は元パス単位で再結合**しないとfill-ruleの穴が壊れて真っ黒になる(cluster_slicer実装済み)
3. **vtracerのtranslate**: 各パスにtransform=translateが付く。bbox計算に必ず反映
4. **背景全面パス**: binaryトレードはキャンバス大の背景パスを吐く→面積25%超は除外
5. **格子切りは使わない**: シートの行ズレ・はみ出しに弱い。成分(連結成分)ベースで「1グループ=1ポーズ」を守るのが正解。行帯でラスタを直裁ちすると隣の足が写り込む
6. **fill vs stroke**: fill(塗り輪郭)はstrokeの約4倍重いが線の強弱が残る。座標を小数2桁に丸めると-40%
7. **入力健診**: 真っ黒PNG(書き出し事故)や自作検品シートの混入をdark率で弾く(process_sheet実装済み)
8. **表示互換**: `<text>`+writing-modeは環境依存で崩れる→vtext.pyで必ずパス化
9. **番号除去は位置ルールで**: 固定ゾーン判定は顔が小さいセルですり抜ける。「最大成分の上端より上=全撤去」が最も頑健
10. **re.subの置換文字列にJSON/SVGを渡さない** — `\n`等が実文字に化けて壊れる。必ず `re.sub(pat, lambda m: text, s)` のlambda置換で。生成したHTML/JSは出荷前にesprima等で構文lint
11. **SVG座標丸めはtransform属性を退避してから** — 素朴なre.subは白マスクの scale(1.95) を scale(1) に切り捨ててマスクが縮み大量透けする。svg_shrink.pyを使う。外部から来た「圧縮済み」素材も採用前に透け検品を必ず通す
12. **軽量再トレース時のマスク消失** — 白マスク付きセルを白背景でラスタ化すると下敷きが消えて背景が透ける。灰色(#808080)地でラスタ化し「>200=白マスク領域」「<100=線」を分離トレースして白fill+線の2層で再構成する
13. **寄りカット×back/lowは発注段階で破綻しやすい**(目の後ろ、口のアオリ等)。発注文で「斜め後ろで可」等の逃げ道を書くか最初から欠番にする。影シルエットは「輪郭内を完全に黒でベタ塗り」と明記しないと白抜きが来る

## 自動トーン(リッチ化・任意)

`auto_tone.py <in.svg> <out.svg> [髪色] [服色]` で線画セルに3層トーンを自動挿入:
髪=シルエット上端接続領域の全塗り(目検出で顔窓を白抜き)/服=中下部の大領域/陰=左上光源のcel shading(顔帯は陰なし)。
ヒューリスティックなので当たり8割 — 検品オーバービューを人間に見せ、外れたIDだけ調整・手直し(一筆塗り工房等)する運用。
キャラ別の推奨: 明るい髪は#ececec系、暗い衣装は#cfcfcf系など、カラー設定の明度関係を反映する。

## 品質ルール(演出)

- ビートは無言が基本。セリフを載せるなら3コマ目に短く1個
- SFXの決め文字(center_back系)も含めキャラに被せない
- 大ゴマは1ページ1つ。3段等分は淡々とした日常、4段は畳みかけ
- 効果背景(BG086〜)は感情の強いコマで実背景の代わりに使うと省エネかつ雄弁

## 進め方の型

1. ユーザーの小説(または要約)を受け取り、シーンをページ数に割る(1ページ=3〜6コマ、8ページ≒1エピソード)
2. 各ページのネームJSONを書く(辞書IDのみ使用。使用キャラのライブラリ有無を characters.json で確認)
3. 全ページレンダ→右綴じ配置のコンタクトシート(P1が右上)を作って提示
4. フィードバックはJSONの該当行を直すだけ。素材の欠落は「未納品」表示で止まらず出るので、後追い発注できる
